# DLLMQuant для LLaDA

Реализация **DLLMQuant** ([arXiv:2508.14090](https://arxiv.org/abs/2508.14090),
Chen Xu, Dawei Yang) — post-training квантование W4A4 для диффузионных языковых
моделей — для **LLaDA-1.5-8B** (основная цель) и **LLaDA2.0** MoE (адаптер
подготовлен, см. раздел про ограничения).

Официального кода авторы не выкладывали, поэтому всё написано по тексту статьи.
Численного совпадения с опубликованными таблицами не гарантируется — в статье
опущены формулы весов и границы бакетов, конкретные выборы отмечены ниже в
разделе «Что домыслено».

## Статус проверки

Честное разделение, потому что оно определяет, чему можно верить:

**Адаптер подтверждён на реальных весах LLaDA-1.5-8B** (`scripts/selfcheck.py`, H200,
transformers 4.46.3): 32 блока найдены по `model.transformer.blocks`, `mask_id 126336`
декодируется в `<|mdm_mask|>`, денойзинг сводит долю масок 1.00 → 0.12, проба внимания
даёт корректный softmax, план поворота покрывает все 7 линейных слоёв блока, поворот
инвариантен на всех долях маскирования.

Измеренный побочный результат: канальные выбросы активаций растут с долей маскирования
(crest factor 6.9 при полностью раскодированной последовательности против **39.1** при
полностью замаскированной) и после поворота выравниваются до ~3 на всех стадиях. То есть
худший для квантования режим — начало генерации, откуда ошибка идёт через все шаги.

## Что это НЕ делает

Квантование **симулированное** (fake quant): значения округляются на 4-битную
сетку и тут же разворачиваются обратно в bfloat16. Это точно измеряет потерю
качества от W4A4, но:

- **не ускоряет инференс** — матричные умножения по-прежнему идут в bf16;
- **не уменьшает чекпоинт на диске** — каждый вес занимает 2 байта, просто
  принимает одно из 16 значений.

Заявленные в статье 1.6× ускорения и 3.2× памяти требуют INT4-ядер (CUTLASS /
Marlin / QuaRot-kernels). Вы выбрали режим «W4A4 как в статье» — это стенд для
замера деградации точности. Если понадобится реально деплоить, нужен W4A16 с
упаковкой весов (`dllmquant.config.w4a16()` даёт конфиг, но упаковку и ядра
надо добавлять отдельно).

## Три компонента и где они в коде

### TMAS — [`dllmquant/calib/tmas.py`](dllmquant/calib/tmas.py)

У DLLM нет одного распределения активаций — оно своё на каждом шаге
расшумления. Ранние шаги видят почти сплошные `[MASK]`, поздние — почти готовый
текст. Калибровка на обычном тексте не видит ни того, ни другого.

TMAS прогоняет настоящие траектории денойзинга, снимает промежуточные состояния,
раскладывает по бакетам доли маскирования и берёт калибровочный набор с
U-образной аллокацией 0.3 / 0.2 / 0.2 / 0.3 — больше бюджета на два края.

### IA-AQ — [`dllmquant/algos/ia_aq.py`](dllmquant/algos/ia_aq.py)

Важный момент реализации: **по-токенное динамическое квантование делает
взвешивание по важности бессмысленным** — у каждого токена своя шкала, токены не
мешают друг другу. Поэтому V квантуется с гранулярностью `per_feature`: одна
шкала на канал, общая для всех токенов. Тогда токен с наибольшей амплитудой
задаёт шаг сетки всем остальным, и появляется что оптимизировать.

Важность токена = колоночная масса softmax-матрицы (сколько внимания к нему
обращено). Шкала выбирается минимизацией взвешенной по важности MSE. Матрица
внимания нужна только на калибровке — шкала замораживается, инференс ничего не
доплачивает.

### CGQ — [`dllmquant/algos/cgq.py`](dllmquant/algos/cgq.py)

GPTQ строит `H = 2·X·Xᵀ`, считая все токены равноценными. В DLLM
последовательность — смесь двух популяций: уже раскодированные позиции
(зафиксированы до конца генерации) и замаскированные (их вот-вот зафиксируют).

```
H = 2 · X · diag(c) · Xᵀ
c_j = unmasked_weight                 если токен раскодирован
      masked_base + beta · conf_j     если токен замаскирован
```

### QuaRot — [`dllmquant/algos/quarot.py`](dllmquant/algos/quarot.py), [`dllmquant/rotate.py`](dllmquant/rotate.py)

**Этого в статье нет** — там QuaRot ([arXiv:2404.00456](https://arxiv.org/abs/2404.00456)) только базлайн для сравнения. Добавлено сверх статьи, потому что три её компонента не закрывают канальные выбросы активаций. Выключено по умолчанию, включается флагом `--rotate`.

Три компонента статьи и поворот работают по **разным осям**:

```
                 каналы (hidden dim) →
   tok0  [  0.3   0.5   0.2  ...  47.1 ]
   tok1  [  0.4   0.1   0.6  ...  52.8 ]   ← выброс по КАНАЛУ → QuaRot
   tok3  [ 31.0  28.4  35.1 ...  44.0 ]   ← выброс по ТОКЕНУ → IA-AQ
```

Механика — вычислительная инвариантность: для ортогональной `Q` вставка `QQᵀ = I` между остаточным потоком и всеми читающими/пишущими его слоями не меняет функцию сети, но переводит активации в базис, где ни один канал не выделяется. Перед поворотом усиление RMSNorm вплавляется в следующие слои — без этого норма с поворотом не коммутирует.

Нумерация поворотов — как в оригинале:

| | Что | Статус |
|---|---|---|
| **R1** | поворот скрытого состояния (остаточный поток) | реализован, вплавлен в веса |
| **R2** | онлайн-Адамар перед down-проекцией FFN | реализован, включён по умолчанию |
| **R3** | поголовный поворот проекций значений | реализован, вплавлен в веса |
| **R4** | онлайн-поворот Q и K после RoPE | функция и тесты есть, установка в модель — нет (см. ниже) |

Числовой режим статьи воспроизведён пресетом `quarot_w4a4()`: активации симметрично по токенам с **постоянным коэффициентом клиппинга 0.9** (не поиск — после поворота искать уже нечего), веса — поиск клиппинга по квадратичной ошибке. Для KV-кэша QuaRot использует асимметричное квантование группами по 128 с коэффициентом 0.95.

**Про R4 и диффузию.** В авторегрессионной модели R4 существует ради квантования KV-кэша — он там узкое место по памяти. У ванильной LLaDA кэша нет вообще: внимание двунаправленное, любой токен может измениться на следующем шаге, ключи и значения пересчитываются заново. Поэтому здесь R4 даёт вторую половину исходной пользы — делает квантуемыми сами Q и K, чтобы матмул скоров шёл в INT4. Исходная мотивация возвращается для блочных декодеров (приближённый KV-кэш Fast-dLLM, переиспользование кэша в LLaDA2.0).

Сама операция реализована и проверена (`rotate_qk`: `(QH)(KH)ᵀ = QKᵀ` с точностью 1e-10), но **встраивание в модель — нет**: R4 обязан применяться после RoPE, а значит не вплавляется в веса и требует патча forward-метода внимания, которого remote-code файл LLaDA не предоставляет. Флаг `qk_heads` выключен, и это осознанный пробел, а не забытая строка.

**Чего ещё нет относительно оригинала.** Q, K и сама матрица внимания в этом пайплайне остаются в bf16, поэтому R4 сейчас не на что подействовать — он окупается только вместе с квантованием Q/K.

**`R2` бьёт прямо в IA-AQ**: V — это тензор, который IA-AQ квантует, и после поворота в нём не остаётся канального выброса, под который приходилось подгонять общую пошкальную сетку.

Что здесь специфично для диффузии:

1. **Эмбеддинг маски поворачивается вместе со всем остальным.** На ранних шагах почти все позиции несут один и тот же вектор — строку `[MASK]` из матрицы эмбеддингов. Она поворачивается как строка `E`, и именно это сохраняет инвариантность при высокой доле масок.
2. **Инвариантность проверяется вдоль траектории, а не в одной точке.** У плотной LLM один режим активаций, у DLLM — от полностью замаскированного до полностью раскодированного. `apply_quarot` сверяет выход на долях маскирования 1.0 / 0.75 / 0.5 / 0.25 / 0.0 и **падает с ошибкой**, если расхождение превысило допуск: поворот обязан быть точно инвариантным, и пропущенный слой должен ронять запуск, а не тихо портить точность через два часа.
3. **Порядок относительно остальных компонент.** Поворот применяется **до** калибровки TMAS, иначе гессианы CGQ и шкалы IA-AQ окажутся посчитаны в базисе, в котором модель работать не будет.

Ширины LLaDA покрыты конструкциями: 4096 и 128 — Сильвестр, 12288 = 12 × 1024 — Кронекер с матрицей Пэли порядка 12. Для непокрытых размеров — случайная ортогональная матрица (инвариантность точная, выбросы размазывает хуже) с предупреждением.

## LLaDA2.0 (MoE) — статус и ограничения

Адаптер [`dllmquant/models/llada2_moe.py`](dllmquant/models/llada2_moe.py)
написан, но это расширение метода, а не воспроизведение статьи — в статье MoE
нет. Три конкретных проблемы:

1. **Разреженный гессиан.** При 128 снимках × 256 токенов и top-2 из 64
   экспертов на эксперта приходится ~1000 токенов при входной размерности в
   тысячи — гессиан недоопределён. `ExpertCoverage` считает покрытие и
   предупреждает; решатель наращивает демпфирование, но правильный ответ —
   поднимать `--nsamples`.
2. **Веса уверенности не доходят до экспертов.** Веса сопоставляются активациям
   по числу токенов; эксперт получает выборку последовательности, число не
   совпадает — такие слои честно откатываются на равномерные веса и попадают в
   `report.unweighted_layers`. Для маршрутизации нужен индексный тензор роутера;
   `ExpertCoverage` его снимает, но связывание с гессианом эксперта я оставил
   явной задачей, а не догадкой. Для плотной LLaDA-1.5 совпадение точное.
3. **mask_id читается из чекпоинта**, а не захардкожен — у LLaDA2.0 другой
   токенизатор. Если не найдётся, адаптер падает с внятным сообщением.

## Сводное сравнение

Одна команда прогоняет всю матрицу из одних и тех же FP16-весов и печатает таблицу:

```bash
python scripts/compare.py --model GSAI-ML/LLaDA-1.5 --out out/compare.json
```

Восемь строк: две границы (FP16, RTN), метод статьи, три leave-one-out по компонентам, чистый базлайн QuaRot и комбинация. Ablations сделаны на выбывание, а не на добавление: статья заявляет компоненты как совместимые plug-in, значит важен вклад каждого **в присутствии остальных**.

### Метрики

GSM8K — это 200 задач × 256 шагов генерации на строку, для восьми строк неприемлемо. Поэтому основная метрика дешёвая и диффузионно-специфичная — [`eval/fidelity.py`](dllmquant/eval/fidelity.py): на отложенных состояниях траектории сравниваются предсказания FP16 и квантованной модели **в замаскированных позициях** (в раскодированных сэмплер логиты выбрасывает, мерить там нечего):

| Метрика | Что показывает |
|---|---|
| top-1 agreement | доля позиций, где argmax не изменился — то есть токены, которые сэмплер реально зафиксирует |
| KL(FP16 ‖ quant) | повреждение, ещё не перевернувшее argmax, но уже близкое к этому |
| confidence drift | сдвиг максимальной вероятности; систематическое падение меняет **порядок** фиксации токенов при remasking |

Всё это разбито **по долям маскирования**. Агрегат скрывает главное — где именно осела потеря: в начале траектории, откуда ошибка проходит через все оставшиеся шаги, или в конце, где токены фиксируются. Две конфигурации с одинаковым GSM8K могут ломаться в разных местах, и чинить их нужно по-разному.

GSM8K добавляется флагом `--gsm8k`.

## Ablations

```bash
python scripts/evaluate.py --model GSAI-ML/LLaDA-1.5 --quantize --w-bits 4 --a-bits 4 --rtn
python scripts/evaluate.py --model GSAI-ML/LLaDA-1.5 --quantize --w-bits 4 --a-bits 4 --no-ia-aq
python scripts/evaluate.py --model GSAI-ML/LLaDA-1.5 --quantize --w-bits 4 --a-bits 4 --no-cgq-weights
python scripts/evaluate.py --model GSAI-ML/LLaDA-1.5 --quantize --w-bits 4 --a-bits 4 --rotate
```

`--no-cgq-weights` выставляет все веса токенов в 1.0, то есть сводит CGQ к
обычному GPTQ — это прямая проверка вклада уверенности. `--rotate` добавляет
QuaRot поверх метода статьи.

## Что домыслено (статья не даёт формул)

| Место | Что выбрано | Почему |
|---|---|---|
| Границы бакетов TMAS | 4 равных интервала по доле маски, бакет 0 = самый замаскированный | В статье указаны только пропорции 0.3/0.2/0.2/0.3 |
| Формула `c_j` | `0.5` для раскодированных, `0.5 + conf` для замаскированных, нормировка к среднему 1 | Из словесного описания «emphasizing high-certainty masked tokens, reducing focus on decoded regions» |
| Гранулярность V | `per_feature` | Единственная, при которой взвешивание по токенам вообще влияет на результат |
| Нижняя граница поиска клиппинга | 0.05 от полного диапазона | При 0.4 метод не срабатывает на выбросах 50× — поймано тестом |
| Порог веса `weight_floor` | `1e-4` от среднего веса | Ограничивает, насколько крупный выброс метод ещё готов срезать: ~1/√f |
| Порядок решения | 4 последовательные группы (QKV → выход внимания → up/gate → down) | Стандарт GPTQ; в статье не оговорён |
| QuaRot | добавлен сверх статьи, выключен по умолчанию | В статье это базлайн, а не компонент; закрывает канальные выбросы, которых не касается ни один из трёх компонентов |

## Известные грабли

- **`ff_out` в LLaDA — это и down-проекция MLP внутри блока, и выходная голова
  модели.** Наивный подстрочный фильтр оставил бы четверть весов
  неквантованными. Роутеры отсекаются по точному имени листа, пути — по
  подстроке (`DLLMQuantConfig.skip`).
- **RoPE в probe.** Вероятности внимания пересчитываются вручную (fused-ядра
  модели матрицу не материализуют). Если ротационный модуль не нашёлся,
  позиционное вращение не применяется и ранжирование важности становится
  приблизительным. `selfcheck` это печатает.
- **Сравнивать CGQ с RTN нужно на частично замаскированном состоянии.** CGQ по
  построению оптимизирует замаскированные позиции; замер на полностью
  раскодированной последовательности меряет его на той популяции, которую ему
  велели считать второстепенной.
- **Матрицы Пэли несимметричны, матрицы Сильвестра симметричны.** В быстром
  преобразовании Адамара сторона умножения (`y @ H` против `H @ y`) на
  степенях двойки незаметна, а на 12288 = 12 × 1024 даёт неверный результат.
  Тест гоняет обе ветки конструкции.
- **Сравнивать методы, квантующие разное количество тензоров, бессмысленно.**
  IA-AQ дополнительно квантует V, которую RTN-базлайн оставляет в FP16, —
  прямое сопоставление льстит не тому. Вклад IA-AQ меряется отдельно, на одних
  и тех же собранных активациях.
- **`hash()` для строк в Python рандомизируется между процессами.** В тестовом
  токенизаторе это делало калибровочный набор разным от запуска к запуску;
  используется FNV-1a.
